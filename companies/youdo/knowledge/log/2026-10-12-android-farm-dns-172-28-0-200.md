# Android farm DNS switched to 172.28.0.200

## Summary

User explicitly requested the same DNS as the recovered iOS runner on Android farm addresses 30–32. DNS `172.28.0.200` was saved in Netplan and applied to the active link on all three nodes. Fresh system resolver checks pass for GitLab, Loki and the OpenAI API name; GitLab HTTPS returns HTTP 200 on each node. No network/service restart or repository changes.

## Context and actions

- `root@192.168.30.30`: `M-K0056`, interface `enp1s0`.
- `root@192.168.30.31`: `M-K0057`, interface `eno1`.
- `root@192.168.30.32`: `M-K0058`, interface `eno1`.
- Before change: DHCP IPv4, systemd-resolved stub, router DNS `192.168.30.1`; existing per-link dropin contains `Domains=~local ~.` only.
- Read-only preflight verified direct DNS queries to `172.28.0.200` for GitLab and Loki on all nodes.
- Per host backed up `/etc/netplan/50-cloud-init.yaml` to `/root/50-cloud-init.yaml.before-dns-20261012`.
- Added `nameservers.addresses: [172.28.0.200]` and `dhcp4-overrides.use-dns: false` under the existing Ethernet interface, retaining DHCP addressing.
- Ran `netplan generate` (all exit 0), then `resolvectl dns <interface> 172.28.0.200` (all exit 0) for immediate resolver update without restarting networking. Existing routing domains retained.

## Verification

On each host:

- `resolvectl dns`: only `172.28.0.200` for the active link.
- Generated `/run/systemd/network/10-netplan-<interface>.network` has `DNS=172.28.0.200` and `UseDNS=false`.
- `resolvectl query gitlab.youdo.sg`: `138.16.203.174`, network response in 18–21 ms.
- `resolvectl query loki.dev.youdo.corp`: `10.16.26.101`, response in 18–20 ms.
- `getent ahostsv4 api.openai.com`: `10.255.0.31` (DNS behavior only; API access not tested).
- Ordinary TLS-validating curl to `https://gitlab.youdo.sg/users/sign_in`: HTTP 200.

## Changed files and limits

Remote `/etc/netplan/50-cloud-init.yaml` and its generated networkd configuration changed on all three nodes; backups retained in `/root`. Current resolver DNS updated through resolvectl. Existing `.local` catch-all dropin unchanged. Local KB log, system map and sync notes updated. No repository modifications or farm workload restarts. Netplan persists the configuration for normal future network initialization; a separate future cloud-init configuration regeneration may overwrite its cloud-init-owned YAML. No such regeneration was performed or tested. Existing Docker container resolver configurations were not modified or independently verified.
